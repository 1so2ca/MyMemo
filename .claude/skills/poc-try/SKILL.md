# poc-try

コードは `poc/<topic>` ブランチの `/poc/<topic>/` 配下のみ。

## サイクル

1. 仮説 — 対象の検証項目を `docs/poc-findings.md` から特定（無ければ先に追記）。「何が観測できれば成功 / 失敗か」と時間箱を宣言し、承認を得る
2. 最小コード — 検証に必要な 1 点だけ。変更内容を要約して承認を得る
3. 観測 — 出力を加工せず提示。失敗もスタックトレースのまま見る
4. 判定 — 仮説どおり / 反証された / 判定不能。「判定不能」を「たぶん動く」で埋めない
5. 記録 — `/poc-log`
6. 次 — 続行 / 打ち切り / 検証項目の見直し を提示して承認を得る

## ガードレール

- 抽象化しない（レイヤ分割・インタフェース・DI・設定ファイル化）
- テスト・厳密な型を書かない。実行して目で見る
- 動いたら止める。整形・リファクタ・エラーハンドリング追加へ進まない
- 例外を握りつぶさない
- モック・固定値は可。ただし検証対象そのものを固定値で通さない。検証にならないので停止して代替案を出す
- 依存追加は検証に必須のものだけ
- 時間箱超過は「判定不能」として記録し止める
